## Question

How does Firstmate's ask-user-authority skill, decision-hold-lifecycle skill/doc, and wake-queue drain path (`bin/fm-wake-drain.sh`, `bin/fm-wake-lib.sh`, `bin/fm-gate-refuse-lib.sh`) distinguish authority questions from permission prompts, queue them, and drain them back to the human, and what should `pi-subagents`' `/sa-decisions-backlog` draining algorithm and authority/permission taxonomy adopt?

## Answer

Firstmate does not classify queue items into "authority" vs "permission" at the mechanical layer: `bin/fm-classify-lib.sh`'s `_fm_decision_fold_line` treats `needs-decision:` and `blocked:` status-line verbs identically — both open a keyed decision (`[key=slug]` token, default key `default`), and only an explicit `resolved`/`captain-held` line for that exact key closes it; a later unrelated status line never silently clears it. The actual "does this need the human" judgment is made upstream by the `.agents/skills/ask-user-authority/SKILL.md` procedure, an agent-side reasoning checklist (does the fix stay within the accepted contract, is it destructive/irreversible/security-sensitive) — there is no script gate for this, only escalation criteria the agent applies before ever writing the decision. Draining is handled by `bin/fm-wake-drain.sh` against a durable append-only wake queue (`$STATE/.wake-queue`, tab-separated epoch/seq/kind/key/payload, deduped per kind+key via `fm_wake_print_deduped`); the caller must explicitly acknowledge consumption with `--ack-through SEQ --recovery-generation GEN` before entries are considered drained, and every drain (even an empty-queue fast path) also prints an `OPEN DECISIONS` section sourced from `scan_open_decisions_incremental`, a per-status-file byte-offset cursor (`fm-classify-lib.sh`) that folds only newly appended bytes since the last call so cost never grows with total log history, and falls back to a full re-fold only on cursor/ident mismatch. Decisions that need to durably outlive a single review become human-facing backlog items via `bin/fm-decision-hold.sh` (owned by `.agents/skills/decision-hold-lifecycle/SKILL.md`): `hold` creates an idempotent `kind captain` backlog item keyed `<origin-id>-decision-<key>`, `complete` requires an explicit inventory of every open key or an explicit `--none` attestation (never inferred from prose), and `resolve` only closes the hold after writing a decision digest plus the exact routed dependent-task ids and clearing their `blocked-by` edges. `bin/fm-gate-refuse-lib.sh` is unrelated to per-request refusal-vs-escalation policy — it is a fleet-lifecycle safety chokepoint that hard-exits (`exit 3`) `fm-spawn.sh`/`fm-send.sh`/`fm-teardown.sh` when the *calling process itself* looks like a no-mistakes gate agent (via `NO_MISTAKES_GATE` env or its worktree's git-common-dir under `.no-mistakes/repos/*.git`), not a mechanism that decides whether a subagent's individual request should be auto-refused instead of escalated.

**Recommendation for `pi-subagents`**:
1. Model the drain loop's cost bound on `scan_open_decisions_incremental`: persist a small per-subagent cursor (byte offset + file identity) so each `/sa-decisions-backlog` cycle folds only newly appended status.json/log bytes since its last run, not the whole session history, with automatic fallback to a full re-fold on cursor/ident mismatch (rotation, truncation, version bump).
2. Require an explicit ack step before a drained item is considered handled, mirroring `fm-wake-drain.sh`'s `--ack-through SEQUENCE --recovery-generation GENERATION`: the backlog loop should only stop re-presenting a permission/authority prompt after `subagents_respond` has confirmed delivery, not merely after displaying it — so a crash mid-response leaves it re-drainable rather than silently lost.
3. Do not collapse `prompt_type` into a single generic "open decision" verb the way Firstmate's `needs-decision|blocked` fold does — since pi-subagents already tags permission vs authority structurally in `status.json`, keep that field as the sole classifier driving response affordance (approve/deny UI vs multi-choice/freeform UI) in the backlog loop, which is a real improvement over Firstmate's collapsed treatment.
4. Add an explicit "reviewed, nothing pending" attestation per drain cycle modeled on `fm-decision-hold.sh complete --none`: never let silence stand in for "no decisions open" — record either the response ids handled or an explicit none-marker, giving the Driver Turn-End Guard a durable, inspectable log to check against instead of re-deriving state from prose.
5. Do not port `fm-gate-refuse-lib.sh` as a model for "refuse outright vs escalate to human" — that script solves an unrelated problem (refusing an entire class of caller identity from touching fleet lifecycle). Instead, build outright-refusal as agent-side policy applied before a subagent ever writes a `prompt_type` entry (following the `ask-user-authority` escalation boundary: destructive/irreversible/security-sensitive always escalates, contract-preserving fixes can proceed autonomously), keeping that judgment out of the queue/drain mechanics entirely.
