## Question

What stuck-process / deadlock detection and recovery patterns does Firstmate implement (stuck-crewmate-recovery skill, `docs/wedge-alarm.md`, `bin/fm-tangle-lib.sh`, `tests/fm-tangle-guard.test.sh`), and what should `pi-subagents` adopt to detect and recover a hung subagent (stuck mid-tool-call, wedged TTY, orphaned worktree lock) beyond simple PID liveness?

## Answer

Firstmate treats "alive but wedged" as a distinct failure mode from PID death, detected two ways. First, `docs/wedge-alarm.md` describes the away-mode daemon (`bin/fm-supervise-daemon.sh`) injecting keystrokes into Firstmate's own pane; if it cannot confirm the submit landed within `FM_MAX_DEFER_SECS`, `inject_wedge_alarm` fires a rate-limited, process-group-bounded, best-effort external notification (osascript/herdr/`command:`) so a TTY that stopped accepting input doesn't stay invisible to an unattended captain. Second, `.agents/skills/stuck-crewmate-recovery/SKILL.md` defines a behavioral escalation ladder for a crewmate that is looping, repeatedly confused, asking an already-answered question, or unresponsive: peek the pane, then answer/redirect via `fm-send`, then `fm-control.sh interrupt`, then — only if "genuinely wedged after redirection" — `fm-control.sh relaunch --note '<progress>'`, which stops the agent and relaunches the same brief plus a progress note into the *same* worktree/branch (never a fresh spawn, to avoid splitting one task across two copies), restoring the prior record if the replacement fails to start; a second relaunch failure is recorded as `failed` and reported plainly. Separately, `bin/fm-lock-lib.sh` supplies a fail-safe staleness proof for orphaned locks/worktrees left by a killed process: a lock is only treated as abandoned if it exists, `lsof` proves no live process holds the lock file or the companion worktree/`.git` dir open, and its mtime age exceeds a caller-supplied minimum — any uncertainty (missing lsof, lsof error, unreadable mtime) defaults to "not stale, leave it alone." `bin/fm-tangle-lib.sh` is a related but distinct guard: it detects a crewmate having branched/committed in the *primary* checkout instead of its own worktree (a named non-default branch where only detached-HEAD-on-default is legitimate), not a hung process.

**Recommendation for `pi-subagents`**:
1. Add a "confirmed-input" wedge check independent of PID liveness: when sending a control message/keystroke into a subagent's Zellij pane, require positive confirmation the input landed within a bounded timeout (Firstmate's `FM_MAX_DEFER_SECS`/`inject_wedge_alarm` pattern); if unconfirmed, escalate rather than assuming success.
2. Implement a graduated recovery ladder instead of binary kill/restart: peek pane output first, then send an interrupt + redirect, and only escalate to forced kill+relaunch if the subagent is still wedged after redirection — mirroring the stuck-crewmate-recovery skill's peek -> answer -> interrupt -> relaunch sequence.
3. On forced relaunch, preserve task identity: reuse the same worktree/branch and pass the prior progress/brief plus a short note into the replacement, and never allocate a second worktree for a task whose original is still unaccounted for (avoids split-brain work).
4. Cap relaunch attempts (Firstmate uses two): if a second forced relaunch still doesn't recover the subagent, stop retrying — mark the task failed/blocked and surface the concrete state to the user instead of looping silently.
5. Before reclaiming an orphaned worktree or lock file left by a killed subagent, apply a three-part fail-safe staleness proof analogous to `fm_lock_is_provably_stale`: the lock/marker exists, no live process holds it or the worktree dir open (via `lsof`/equivalent), and its age exceeds a minimum threshold — treat any uncertainty as "still live," never force-clean on ambiguous evidence.
6. Add a rate-limited external alarm channel (desktop notification or similar) for stalls that survive the recovery ladder, so a wedge doesn't stay invisible when the user isn't actively watching the Zellij session, following the wedge-alarm's best-effort, timeout-bounded, non-crashing multi-channel dispatch design.
